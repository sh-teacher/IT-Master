Chapter 14. IoT 스마트 온습도 모니터 시스템

Chapter 7(DHT11), Chapter 9(I2C LCD), Chapter 10(무선 통신)의 핵심 기술을 모두 결합한 종합 프로젝트입니다. 온습도 센서 데이터를 로컬 LCD에도 표시하면서 동시에 웹 브라우저에서 실시간으로 모니터링할 수 있는 스마트 홈 IoT 기기를 만들어봅니다.

💡 이 프로젝트에서 배우는 것

  • 비동기 프로그래밍(Async) - 센서 읽기와 웹 서버를 동시에 구동
  • 실시간 데이터 수집 - DHT11 센서를 2초 주기로 읽고 저장
  • 멀티 출력 - 같은 데이터를 LCD와 웹에 동시 표시
  • RESTful API - 브라우저에서 JSON 데이터 수신
  • 반응형 UI - 스마트폰과 PC에서 모두 보기 좋은 대시보드

DHT11: VCC→3V3, Data→GP15, GND→GND. LCD는 SDA→GP8, SCL→GP9에 연결하고, 측정값은 LCD와 웹 대시보드로 동시에 전달됩니다.

14.1 프로젝트 개요 및 준비물

이 프로젝트는 센서 입력, 로컬 출력(LCD), 원격 접근(웹)의 세 가지 레이어를 동시에 구동합니다. 비동기 프로그래밍(asyncio)을 활용해 센서 읽기와 웹 서버가 서로 방해하지 않고 독립적으로 작동하도록 설계했습니다.

부품 Pico 핀 역할 참고
DHT11 온습도 센서 GP15 온도·습도 데이터 입력 Chapter 7 참고
I2C LCD 16x2 GP8 (SDA), GP9 (SCL) 로컬 LCD 디스플레이 Chapter 9 참고
내장 Wi-Fi — 무선 네트워크 연결 Chapter 10 참고
전원 3V3, GND 공통 전원 & 접지 모든 부품 GND 공통

14.2 전체 소스 코드

이 코드는 세 가지 작업을 동시에 처리합니다:

  1. read_sensor_loop() - 2초마다 DHT11을 읽고, LCD와 웹 데이터 업데이트
  2. start_webserver() - 포트 80에서 HTTP 요청 대기, JSON 응답 및 HTML 페이지 제공
  3. main() - 둘을 asyncio로 동시 구동
import network
import time
import ujson
import uasyncio as asyncio
from machine import Pin, I2C
import dht
from lcd_i2c import I2cLcd

# ================= 설정 =================
WIFI_SSID = "여기에_와이파이_이름"
WIFI_PASSWORD = "여기에_와이파이_비밀번호"

DHT_PIN = 15
I2C_SDA_PIN = 4
I2C_SCL_PIN = 5
LCD_ADDR = 0x27          # i2c.scan() 결과로 확인 후 수정
READ_INTERVAL = 2        # 센서 읽는 주기(초). DHT11은 1초 이상 권장

# ================= 초기화 =================
sensor = dht.DHT11(Pin(DHT_PIN))
i2c = I2C(0, sda=Pin(I2C_SDA_PIN), scl=Pin(I2C_SCL_PIN), freq=400000)
lcd = I2cLcd(i2c, LCD_ADDR, 2, 16)

latest = {"temp": None, "humi": None, "updated": 0, "error": None}


def connect_wifi():
    wlan = network.WLAN(network.STA_IF)
    wlan.active(True)
    wlan.connect(WIFI_SSID, WIFI_PASSWORD)

    lcd.clear()
    lcd.putstr("WiFi connecting")

    for _ in range(20):
        if wlan.isconnected():
            break
        time.sleep(1)

    if wlan.isconnected():
        ip = wlan.ifconfig()[0]
        print("Wi-Fi 연결됨:", ip)
        lcd.clear()
        lcd.putstr("IP:")
        lcd.move_to(0, 1)
        lcd.putstr(ip)
        time.sleep(2)
        return ip
    else:
        print("Wi-Fi 연결 실패")
        lcd.clear()
        lcd.putstr("WiFi Failed")
        return None


# ================= 센서 읽기 + LCD 갱신 루프 =================
async def read_sensor_loop():
    while True:
        try:
            sensor.measure()
            t = sensor.temperature()
            h = sensor.humidity()

            latest["temp"] = t
            latest["humi"] = h
            latest["updated"] = time.time()
            latest["error"] = None

            lcd.clear()
            lcd.putstr("Temp: {:>2d} C".format(t))
            lcd.move_to(0, 1)
            lcd.putstr("Humi: {:>2d} %".format(h))

            print("온도: {}C  습도: {}%".format(t, h))
        except OSError as e:
            latest["error"] = str(e)
            print("센서 읽기 오류:", e)
            lcd.clear()
            lcd.putstr("Sensor Error")

        await asyncio.sleep(READ_INTERVAL)


# ================= 웹 페이지 =================
HTML_PAGE = """




Pico 온습도 모니터



  
실시간 온습도 모니터

  

    

      
--

      
온도 (C)

    

    

      
--

      
습도 (%)

    

  

  
불러오는 중...

  





"""


async def handle_client(reader, writer):
    request_line = await reader.readline()
    # 나머지 헤더 비우기
    while True:
        line = await reader.readline()
        if line in (b"\r\n", b""):
            break

    try:
        request = request_line.decode()
    except Exception:
        request = ""

    if "GET /data" in request:
        body = ujson.dumps(latest)
        response = (
            "HTTP/1.1 200 OK\r\n"
            "Content-Type: application/json\r\n"
            "Access-Control-Allow-Origin: *\r\n\r\n" + body
        )
    else:
        response = (
            "HTTP/1.1 200 OK\r\n"
            "Content-Type: text/html; charset=utf-8\r\n\r\n" + HTML_PAGE
        )

    await writer.awrite(response)
    await writer.aclose()


async def start_webserver():
    print("웹 서버 시작: 포트 80")
    await asyncio.start_server(handle_client, "0.0.0.0", 80)
    while True:
        await asyncio.sleep(3600)


async def main():
    connect_wifi()
    await asyncio.gather(read_sensor_loop(), start_webserver())


asyncio.run(main())

14.3 동작 원리 상세 분석

🔄 asyncio.gather()는 뭐하는 거예요?

일반 Python은 while True 루프 하나가 CPU를 독점하면, 다른 작업은 대기합니다. 하지만 await asyncio.sleep()에서 대기할 때는 CPU 시간을 남에게 양보할 수 있어서, 여러 작업이 번갈아 실행됩니다. asyncio.gather()는 이런 두 개 이상의 비동기 함수를 동시에 실행하고, 모두 끝날 때까지 대기합니다.

# gather 없이 실행하면
await read_sensor_loop()          # 이 루프가 끝날 때까지
await start_webserver()            # 이건 절대 실행 안 됨!

# gather로 실행하면
await asyncio.gather(
    read_sensor_loop(),            # 둘 다 동시 실행
    start_webserver()              # 센서 읽기 중에도 웹 요청 처리 가능
)

📡 HTTP 요청은 어떻게 처리되나요?

  • GET /data - 브라우저가 JSON 데이터를 요청 → latest 딕셔너리를 JSON으로 변환해 응답
  • GET / (나머지 경로) - 브라우저가 처음 접속 → HTML 페이지 전송
  • 각 요청마다 asyncio.start_server()가 클라이언트와 연결을 맺고, handle_client()가 요청 처리 후 연결 종료

예제 2. LCD 주소 자동 찾기

LCD 모듈마다 I2C 주소가 다를 수 있으니, 시작 시 자동으로 주소를 스캔해서 첫 번째 응답하는 주소를 사용합니다.

💻자동 스캔 코드 보기 
# Pico 스크립트에서 기존 코드 전에 추가
def find_i2c_lcd():
    i2c = I2C(0, sda=Pin(I2C_SDA_PIN), scl=Pin(I2C_SCL_PIN), freq=400000)
    addrs = i2c.scan()

    if not addrs:
        print("I2C 장치를 찾을 수 없습니다")
        return None

    addr = addrs[0]
    print(f"I2C LCD 주소 발견: 0x{addr:02x}")

    try:
        lcd = I2cLcd(i2c, addr, 2, 16)
        lcd.putstr("LCD Found!")
        return lcd
    except Exception as e:
        print(f"LCD 초기화 실패: {e}")
        return None

# 기존 코드 수정
lcd = find_i2c_lcd()
if lcd is None:
    print("LCD 없이 계속 진행하거나 종료해야 함")

14.5 트러블슈팅

웹 브라우저에서 "IP:80 접속할 수 없음" 오류
  • Pico의 Wi-Fi 연결 확인 - 콘솔 출력에서 "연결됨" 메시지와 IP 주소가 표시되는지 확인
  • 같은 네트워크 확인 - 스마트폰/PC가 Pico와 동일한 Wi-Fi 네트워크에 연결되었는지 확인 (게스트 네트워크 아님)
  • 방화벽 확인 - 학교 네트워크의 경우 포트 80이 차단될 수 있으니 IT 관리자 문의
  • IP 주소 재확인 - Pico의 부팅 메시지에서 표시되는 IP를 정확히 입력했는지 확인
LCD는 표시되는데 웹에서 "–" 만 보임
  • 콘솔 메시지 확인 - "온도: XX C 습도: XX%" 가 계속 출력되는지 확인
  • 센서 읽기 오류 확인 - "센서 읽기 오류" 메시지가 반복 출력되면 DHT11 배선 재확인
  • 웹 연결 확인 - http://[IP]/data 에 직접 접속해서 JSON이 반환되는지 확인
여러 사람이 동시에 접속할 때 가끔 연결 끊김
  • 동시 연결 제한 - Pico의 제한된 메모리 때문에 한 번에 한 명씩만 처리 가능합니다. 여러 명이 동시 접속 시 일부 연결이 타임아웃될 수 있음
  • 해결책 - 더 복잡한 웹 서버가 필요하면 Chapter 11의 MQTT 클라우드 방식 검토
